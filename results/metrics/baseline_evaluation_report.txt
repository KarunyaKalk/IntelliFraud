6. DATA LEAKAGE AND LIMITATIONS OF THE ORIGINAL EVALUATION
==========================================================================
 1. Train/test duplicates: 344 test rows have an exact copy in the training set; 336 normal test rows were literally seen by the Autoencoder during training. See section 4 for their effect.
 2. Duplicates inside the test set: 70 extra copies are counted more than once.
 3. Threshold chosen on training data the model had already fitted (and the same rows fed early stopping). Training errors are optimistically low, so the threshold tends to be too low -> more false alarms on new data. No separate validation set of normal rows exists.
 4. Random (not time-based) split over 48 hours: the model learned from transactions that happen AFTER some test transactions, and 'Time' is used as an input feature.
 5. Small number of test frauds (98): one fraud changes recall by about 1.02 percentage points - see the wide confidence intervals.
 6. Accuracy is misleading: 94.75% looks high but is below the 99.83% of a model that never predicts fraud.
 7. The 95th-percentile rule flags about 5% of normal traffic by design: 2,978 false alarms, 35.0 per fraud caught.
 8. Possibly undertrained: 10 epochs, validation loss still decreasing, early stopping never triggered.
 9. Not exactly reproducible: no TensorFlow random seed was set, so retraining gives different weights.
10. Model provenance: the scaler statistics match training-normal rows exactly, but the weights file itself cannot prove which rows it was trained on.
